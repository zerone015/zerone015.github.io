각 테스트가 무엇을 검증하는지 단계별로 정리한다. 모든 테스트는 끝나면 QEMU 디버그 콘솔에 완료 마커를 출력한다. `./scripts/test.sh`는 모든 테스트를 실행해 마커를 확인하고, 출력 결과로 통과 여부를 판정한다.

테스트 스크립트: [scripts/test.sh](https://github.com/zerone015/kfs/blob/master/scripts/test.sh)

## Physical Memory

각 단계가 끝날 때마다 free 페이지 수가 사용 가능한 전체 페이지 수와 같은지 확인한다.

- **Phase 1.** 오더마다 같은 크기의 블록을 최대 512개 할당한 뒤 모두 해제한다.
- **Phase 2.** 여러 오더를 번갈아 할당한 뒤 모두 해제한다.
- **Phase 3.** 할당된 물리 주소가 BIOS 메모리 맵의 사용 가능 영역 안에 있는지 확인한다.

테스트 코드: [test/pmm_test.c](https://github.com/zerone015/kfs/blob/master/test/pmm_test.c)

## Kernel Virtual Address Space

할당할 때마다 주소의 범위와 4MB 정렬을 확인하고 값을 써서 지연 할당을 확인한다. 각 단계가 끝나면 빈 블록이 처음 주소와 크기의 블록 하나로 병합됐는지 확인한다.

- **Phase 1.** 4MB 블록 하나를 할당하고 해제한다.
- **Phase 2.** 4MB 블록으로 가용 공간을 전부 할당하고, 추가 할당이 실패하는지 확인한 뒤 모두 해제한다.
- **Phase 3.** 4MB, 8MB, 12MB처럼 크기를 늘려 가며 실패할 때까지 할당하고, 짝수 번째와 홀수 번째 순으로 해제한 뒤 전체 크기의 블록을 다시 할당한다.

테스트 코드: [test/vmm_test.c](https://github.com/zerone015/kfs/blob/master/test/vmm_test.c)

## Heap

- **Phase 1.** 400MB를 한 번에 할당하고 해제한다.
- **Phase 2.** 8B부터 8192B까지 크기별로 다음을 3번 반복해, 해제한 메모리가 재사용되는지 확인한다.
  1. 128MB 한도 안에서 최대 개수를 할당한다.
  2. 청크마다 `a`와 `b`를 번갈아 채우고, 청크끼리 겹치는지 검사한다.
  3. 짝수 번째와 홀수 번째 순으로 해제한다.

테스트 코드: [test/hmm_test.c](https://github.com/zerone015/kfs/blob/master/test/hmm_test.c)

## fork

- **Phase 1.** 부모가 자식을 1000개 만든다. 부모는 `fork`가 반환한 PID가 순서대로인지 확인하고, 자식은 자기 PID를 확인하고 물려받은 값을 바꾼 뒤 결과를 종료 코드로 돌려준다. 부모는 자식을 모두 회수해 정상 종료했는지 확인하고, 자기 값이 그대로인지 확인해 COW를 검증한다.
- **Phase 2.** 자식이 다시 `fork`하는 중첩 fork를 같은 방식으로 확인한다.

테스트 코드: [test/fork_test.c](https://github.com/zerone015/kfs/blob/master/test/fork_test.c)

## wait and exit

- **Phase 1.** `fork`, `exit`, `wait`을 1000만 번 반복하며, 매번 `wait`이 반환한 PID와 종료 상태를 확인한다. 회수할 때 자원이 해제되지 않으면 반복하는 동안 자원이 바닥나 `fork`가 실패한다.

테스트 코드: [test/wait_exit_test.c](https://github.com/zerone015/kfs/blob/master/test/wait_exit_test.c)

## Signal

- **Phase 1.** 실행 중인 자식에게 SIGKILL을 보내고, 회수해서 SIGKILL로 종료됐는지 확인한다.
- **Phase 2.** SIGINT 핸들러를 등록하고 `fork`한 뒤 자식에게 SIGINT를 보낸다. 핸들러는 정해 둔 종료 코드로 자식을 종료시키고, 부모는 회수해서 그 코드를 확인한다.

테스트 코드: [test/signal_test.c](https://github.com/zerone015/kfs/blob/master/test/signal_test.c)

## Panic

- **Phase 1.** 범용 레지스터와 스택에 정해 둔 값을 넣고 `do_panic`을 호출해, 덤프된 값이 같은지 확인한다.
- **Phase 2.** 매핑되지 않은 커널 주소로 점프해 페이지 폴트로 패닉이 발생하는지 확인한다.

테스트 코드: [test/panic_test.asm](https://github.com/zerone015/kfs/blob/master/test/panic_test.asm)
