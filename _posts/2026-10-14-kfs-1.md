이번 글에서는 GRUB이 커널을 메모리에 올린 뒤, C로 작성된 `kmain`에 들어가기까지의 과정을 정리한다.

## Multiboot Specification

GRUB으로 부팅하기 위해 멀티부트 사양을 따른다. 멀티부트 사양은 GRUB이 어떤 커널이든 같은 방식으로 적재할 수 있도록 만든 표준 명세다.

멀티부트 사양에는 1과 2가 있다. 1은 단순하고, 2는 UEFI도 지원한다. KFS는 BIOS로 부팅하기 때문에 더 단순한 멀티부트 1을 따랐다.

멀티부트 1을 따르는 커널은 정해진 형식의 헤더를 가져야 한다. GRUB은 커널 파일의 처음 8KB 안에서 4바이트마다 이 헤더를 찾기 때문에, 헤더는 반드시 파일의 맨 앞 8KB 안에 있어야 한다. 헤더에는 다음 세 필드가 들어간다.

- **magic**: `0x1BADB002`. GRUB은 이 값으로 헤더를 찾는다.
- **flags**: 커널이 부트로더에 요청하는 기능을 비트로 표시한다. 예를 들어 메모리 정보를 넘겨 달라는 요청이 여기에 들어간다.
- **checksum**: magic과 flags를 더한 값의 2의 보수다. 세 값을 모두 더하면 0이 되어야 하고, GRUB은 이걸로 헤더가 진짜인지 검증한다.

## Boot Information

BIOS가 GRUB을 적재하면, GRUB은 BIOS 인터럽트를 통해 하드웨어 정보를 수집해서 메모리에 정해진 구조체(`multiboot_info`) 형태로 저장해 둔다. 그리고 보호 모드로 전환한 뒤 커널을 적재하고, 커널로 제어를 넘기기 직전에 두 레지스터를 채운다.

- **EAX**: 매직 값 `0x2BADB002`. 커널은 이 값으로 멀티부트를 지원하는 부트로더가 자신을 올렸는지 확인한다.
- **EBX**: `multiboot_info` 구조체의 물리 주소.

이 구조체에는 물리 메모리 중 어떤 영역이 예약되어 있고 어떤 영역을 쓸 수 있는지 알려 주는 메모리 맵도 들어 있다. 이 정보는 부팅 시 물리 메모리 관리자를 초기화할 때 꼭 필요하다.

커널은 32비트 보호 모드, 페이징이 꺼진 상태로 제어를 받는다.

## Linker Script

```plaintext
ENTRY(_start)

SECTIONS
{
    . = 0x00100000;

    _kernel_start = .;
    .multiboot.data : { *(.multiboot.data) }
    .multiboot.text : { *(.multiboot.text) }

    . += 0xC0000000;

    .text   : AT(ADDR(.text)   - 0xC0000000) { *(.text) }
    .rodata : AT(ADDR(.rodata) - 0xC0000000) { *(.rodata) }
    .data   : AT(ADDR(.data)   - 0xC0000000) { *(.data) }
    .bss    : AT(ADDR(.bss)    - 0xC0000000)
    {
        *(COMMON)
        *(.bss)
        *(.bootstrap_stack)
    }
    _kernel_end = . - 0xC0000000;
}
```

커널은 물리 주소 1MB부터 적재된다. 멀티부트 헤더가 들어 있는 `.multiboot.data`를 맨 앞에 둬서 헤더가 파일의 처음 8KB 안에 오도록 하고, 그 뒤에 `_start`가 있는 `.multiboot.text`를 둔다. 이 두 섹션은 물리 주소 그대로 링크되기 때문에, 페이징이 꺼진 상태에서도 바로 실행할 수 있다.

그다음 `. += 0xC0000000`으로 위치를 상위 절반으로 옮긴다. 이후 섹션들은 `0xC0100000`대의 가상 주소를 기준으로 링크되지만, `AT()`으로 실제 적재 주소는 `0xC0000000`을 뺀 물리 주소로 지정한다. 즉 코드 안의 주소는 가상 주소로 계산되고, GRUB은 `AT()`에 적힌 물리 주소에 섹션을 올린다.

## _start

부팅 어셈블리 코드: [src/boot/boot.asm](https://github.com/zerone015/kfs/blob/master/src/boot/boot.asm)

커널이 제어를 받으면 `_start` 심볼에서 시작하고, 다음 순서로 진행된다.

1. Identity Mapping
2. Higher Half Mapping
3. EBX에 담긴 `multiboot_info`의 물리 주소를 매핑하고, 해당 가상 주소를 EBX에 다시 대입
4. Temporary Mapping Area
5. Recursive Mapping
6. 제어 레지스터로 페이징 등 필요한 CPU 기능을 켠 뒤 `.higher_half`로 점프

### 1. Identity Mapping

매핑이란 물리 메모리를 가상 주소 공간에 연결하는 작업이다. 페이징에서는 물리 페이지를 가상 주소 공간 어디에나 매핑할 수 있는데, Identity 매핑은 물리 주소와 가상 주소를 똑같이 매핑하는 것이다. 여기서는 RAM의 0~8MB 영역을 가상 주소 `0x0` ~ `0x800000`에 그대로 매핑한다.

이게 필요한 이유는 페이징을 켠 직후에 실행되는 명령어 때문이다. 페이징이 켜지기 전까지는 물리 주소로 메모리에 직접 접근하지만, 페이징이 켜지는 순간부터 CPU는 모든 주소를 가상 주소로 해석한다. 아래는 페이징을 켜는 부팅 코드의 일부다.

```nasm
section .multiboot.text
global _start
_start:
    ...
    mov ecx, cr0
    or  ecx, CR0_BOOT_FLAGS
    mov cr0, ecx                    ; 1
 
    jmp .higher_half                ; 2
```

`_start`의 명령어들은 `.multiboot.text` 섹션에 있고, 이 섹션은 링커 스크립트에서 물리 주소로 링크되도록 정의되어 있다. 1에서 페이징이 켜지면 CPU는 이제 가상 주소만 인식하는데, 다음에 실행할 2의 `jmp` 명령어는 여전히 물리 주소에 있고 EIP도 그 물리 주소를 가리키고 있다. 이때 Identity 매핑이 없으면 명령어를 가져오는 순간 페이지 폴트가 나고, 아직 IDT도 없으니 곧바로 트리플 폴트로 이어져 시스템이 리셋된다.

반면 점프 대상인 `.higher_half`는 `.text` 섹션에 있고, 이 섹션은 링커 스크립트에서 가상 주소로 링크되도록 정의되어 있다. 그래서 Identity 매핑은 물리 주소에서 가상 주소로 건너가기 위한 다리 역할만 하고, 건너간 뒤에는 제거한다.

인텔 매뉴얼에도 이 내용이 나와 있다.

> If paging is enabled, the code for the MOV CR0 instruction and the JMP or CALL instruction must come from a page that is identity mapped (that is, the linear address before the jump is the same as the physical address after paging and protected mode is enabled). The target instruction for the JMP or CALL instruction does not need to be identity mapped.
>
> Intel® 64 and IA-32 Architectures Software Developer's Manual, Vol. 3A, 12.9.1 Switching to Protected Mode

### 2. Higher Half Mapping

인터럽트나 시스템 콜을 처리하려면 커널이 모든 프로세스의 가상 주소 공간에 매핑되어 있어야 한다. 또 커널을 모든 프로세스의 같은 위치에 매핑하면, 커널 페이지를 글로벌 페이지로 설정해서 CR3가 바뀌어도 커널 페이지가 TLB에 남아 있도록 할 수 있다.

상위 절반 매핑은 커널 이미지를 가상 주소 공간의 위쪽에 매핑하는 것이다. 현재 설계에서는 4GB 중 위쪽 1GB(`0xC0000000` ~ `0xFFFFFFFF`)를 커널이, 아래쪽 3GB를 유저가 쓴다. 아래가 아닌 위에 매핑하면 다음과 같은 이점이 있다.

- 커널이 커지더라도 유저 프로그램의 시작 주소가 바뀌지 않는다.
- 64비트 커널에서 32비트 프로그램을 돌릴 때, 커널이 64비트 주소 공간 위쪽에 있으므로 4GB 전체를 유저에게 줄 수 있다.
- 대부분의 유닉스 계열 OS가 커널을 위쪽에 두기 때문에, 기존 코드를 포팅하기 쉽다.

### 3. multiboot_info Mapping

GRUB이 EBX로 넘겨준 `multiboot_info`의 주소는 물리 주소다. 그런데 `kmain`은 페이징이 켜진 뒤에 실행되므로, 이 주소를 가상 주소 공간에 매핑하고 가상 주소로 바꿔서 넘겨야 한다.

이 주소가 속한 4MB 영역을 `0xC0800000`(엔트리 770)에 매핑하고, EBX 값을 `0xC0800000 | (ebx & 0x3FFFFF)`로 바꿔서 가상 주소로 만든다. 이 값은 그대로 `kmain`에 인자로 전달되고, 이 매핑은 물리 메모리 초기화가 끝나면 제거된다.

### 4. Temporary Mapping Area

메모리 관리 편에서 자세히 설명하겠지만, 현재 설계에서 유저 공간은 4KB 페이지를, 커널은 4MB 페이지를 사용한다. 그런데 커널 공간에 4KB 페이지를 잠깐 매핑해야 하는 경우가 있다. 대표적으로 COW를 처리할 때 유저 페이지를 복제하는 경우와, fork할 때 자식의 페이지 테이블을 복제하는 경우다.

이런 경우에 쓰기 위해 엔트리 1022번 영역을 4KB 매핑 전용으로 예약해 둔다. 필요할 때 매핑하고, 작업이 끝나면 해제하는 방식으로 사용한다.

### 5. Recursive Mapping

재귀 매핑은 재귀 페이징을 위한 설정이다. 재귀 페이징은 페이지 디렉터리와 페이지 테이블에 접근할 때마다 따로 매핑하거나 해제할 필요 없이, 간단하게 접근할 수 있게 해 주는 방법이다.

페이지 디렉터리와 페이지 테이블도 결국 메모리에 있는 데이터라서, 커널이 읽고 쓰려면 가상 주소 공간에 매핑되어 있어야 한다. 그런데 상위 절반 커널이라 커널이 쓸 수 있는 가상 주소 공간은 1GB밖에 안 되고, 여기에 모든 페이지 테이블을 고정으로 매핑해 두기는 어렵다.

재귀 페이징을 설정하면 가상 주소 공간 4MB만 써서, 별도의 매핑 없이 현재 주소 공간의 페이지 디렉터리와 모든 페이지 테이블에 접근할 수 있다. 설정은 단순하다. 페이지 디렉터리의 마지막 엔트리(1023번)에 페이지 디렉터리 자기 자신의 물리 주소를 넣으면 된다.

이게 왜 되는지는 페이지 워크 과정을 보면 알 수 있다. PAE를 켜지 않은 x86 32비트의 페이지 워크는 원래 다음 세 단계다.

1. CR3가 가리키는 페이지 디렉터리를 가상 주소의 상위 10비트로 인덱싱해서 페이지 테이블의 주소를 얻는다.
2. 그 페이지 테이블을 가상 주소의 다음 10비트로 인덱싱해서 실제 페이지의 주소를 얻는다.
3. 그 페이지에 가상 주소의 하위 12비트 오프셋을 더해서 원래 접근하려던 주소에 접근한다.

상위 10비트가 1023이면, 1단계에서 얻는 "페이지 테이블"이 사실은 페이지 디렉터리 자신이 된다. 그러면 2단계에서 페이지 디렉터리를 페이지 테이블처럼 인덱싱하게 되고, 3단계에서 도착하는 곳은 일반 페이지가 아니라 페이지 테이블이 된다. 다음 10비트까지 1023이면 한 번 더 자기 자신으로 돌아오므로, 3단계에서 페이지 디렉터리 자체에 도착한다. 예를 들면 다음과 같다.

- **`0xFFC00000`**: 첫 번째 페이지 테이블의 첫 번째 엔트리
- **`0xFFFFF000`**: 페이지 디렉터리의 첫 번째 엔트리

각 프로세스는 자기 페이지 디렉터리의 1023번 엔트리에 자기 자신을 넣어 두기 때문에, 이 방식으로 접근할 수 있는 건 현재 CR3에 올라가 있는 주소 공간의 페이지 테이블뿐이다. 다른 프로세스의 페이지 테이블을 다뤄야 할 때, 예를 들어 fork에서 자식의 페이지 테이블을 채울 때는 앞에서 말한 4KB 임시 매핑 영역을 사용한다.

가상 주소 공간 4MB를 고정으로 희생하는 대신, 페이지 디렉터리와 페이지 테이블을 아주 간편하게 다룰 수 있다.

### 6. Control Registers

매핑이 끝나면 제어 레지스터로 필요한 CPU 기능을 켠다.

- **CR4**: PSE(4MB 페이지 사용), PGE(글로벌 페이지 사용)
- **CR3**: 위에서 채운 페이지 디렉터리의 물리 주소
- **CR0**: PG(페이징), WP(커널 모드에서도 읽기 전용 페이지 쓰기 금지), NE(x87 부동소수점 예외를 #MF로 처리)

CR0에 PG 비트를 켜는 순간 페이징이 활성화되고, 바로 `jmp .higher_half`로 상위 절반 주소로 넘어간다.

## .higher_half

`.higher_half`부터는 가상 주소 기준으로 실행되며, 다음 순서로 진행된다.

1. Identity 매핑 제거 (엔트리 0, 1)
2. CR3를 다시 로드해서 TLB 비우기
3. ESP에 커널 스택을 설정하고, EAX와 EBX를 인자로 넘겨 C 진입점인 `kmain` 호출

## kmain

[src/kernel/main.c](https://github.com/zerone015/kfs/blob/master/src/kernel/main.c)

`kmain`에서는 다음 순서로 초기화를 진행한다.

1. **`arch_init()`**: VGA, TTY, GDT, IDT, PIC 초기화
2. **`bootloader_check()`**: 멀티부트 정보 유효성 검사
3. **`memory_init()`**: 물리 메모리, 가상 주소 공간, 힙 초기화
4. **`scheduler_init()`**: PIT, TSS 초기화
5. **`process_init()`**: 프로세스 자료구조 초기화와 init 프로세스 생성

`process_init()`에서 만드는 init 프로세스는 유저 공간을 직접 구성해서 테스트 코드를 실행하는 역할을 맡는다.
